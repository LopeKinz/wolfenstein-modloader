In plain wordsIn einfachen Worten

This is the entry page of the wiki for Wolfenstein: The New Order (id Tech 5) and Wolfenstein II: The New Colossus (id Tech 6). It explains the three levels of proof used everywhere: measured in the running game, inferred from the program file, or only speculated from a text string. It then lists what works, what does not and what is unverified for each game. In short, The New Order can be read, patched and loaded with mods, while for Wolfenstein II the tool could only read files and not yet write mods at the time.

  • Three proof levels: measured, inferred, speculated; a text in the program file alone proves nothing.
  • TNO: 14/14 rebuilt archives loaded in the game, 48 minutes of play with 0 errors in the log.
  • TNO: new 3D geometry, particle changes and patching the program file do not work.
  • TNC: developer console works; writing mods was not possible yet (no write path).
  • The documents contradicted each other in 20 places; 17 were fixed, 3 remain open.

Technical detailsTechnische Details

Der technische Teil ist auf Englisch – so, wie er im Wiki steht. Unterstrichene Begriffe haben eine Erklärung auf Deutsch.

This directory describes two games and a tool:

  • Wolfenstein: The New Order (id Tech 5, WolfNewOrder_x64.exe) — the SDK reads, patches, and launches this game.
  • Wolfenstein II: The New Colossus (id Tech 6, NewColossus_x64vk.exe) — the SDK locates and launches it, passing Cvars, and now writes its archives too: wolfsdk/tncpatch.py patches its IDCL containers directly (wolfsdk/game.py, TITLES["tnc"].mods = True for both titles). Decl value edits, a BC1 weapon skin, and a full dlc_0-precedence custom map have all been confirmed working in a real, running game — see the table below and TNC Modding Surface.

The tool itself is described in ../README.md. This section contains what has been discovered about the games.

The Most Important Rule: Measured ≠ Speculated

This project is only as valuable as you can trust your claims. Therefore, the documents define three levels of proof, most sharply formulated in Asset-Loading-Paths.md:

Grade Means Example
Measured / RUNTIME In the log of a running game, on the disc, or proven via a run with real data. WARNING: com_allowConsole CANNOT be set in retail! in qconsole.log
Inferred / CVAR Read from the binary; the Name↔Meaning mapping is guessed via neighborhood. The .text of both games is SteamStub-encrypted, there is no call site as proof. fs_overlaypath — "Extra location for game files (with precedence over fs_basepath)"
Speculated / STRING The text exists in the binary, nothing more. A dead code path looks just as good. FSPATH_OVERLAY as an RTTI name

A string in the EXE does not prove that the function exists. How large the difference is shown by TNC-CVar-Validation.md: from 2231 harvested "Cvar names" for Part 2 there are 222 real Cvars, hit rate 10 %. The engine itself knows 304.

For the game launched so far, almost nothing has been done. By far the largest part of all statements about Effect is unverified; statements about Format are mostly not.

Before you believe anything stated here

These documents were created side-by-side in a short time and contradicted each other at 20 places. Raised in Known-Contradictions.md, processed on 21.09.2026: 17 were fixed in the text, 3 remain open with justification — two of which are embedded in the code and belong to other workers.

What changed the direction of the statement so that no one falls back to an old status:

  • The Patcher does not hang onto the file end but writes into the slot; File-Formats.md §3 described up to that point the procedure, which demonstrably leads to a crash (W4).
  • A BIM Encoder exists (wolfsdk/image.py, only RGBA8) — six places explained it as missing (W5).
  • The IDCL Container (Part 2) and the .pages Container (Virtual Textures) are read, not "unsolved" (W8, W9).
  • The 2231 Cvars for Part 2 are candidates; truly present are 222 of 304 (W3).
  • The Slot space is exactly csize, not csize + 15 (W6).

In case of a conflict, the rule remains: the newer, more detailed individual investigation overrides the older summary — and both override the README.

Recalculate Evidence

Every document names the tool from which its numbers originate. All are purely read-only and do not start a game:

python tools/verify_all.py              # all harmless checks
python tools/survey_engine.py           # engine-surface.md
python tools/survey_modding_surface.py  # moddingflaeche-tno.md
python tools/survey_tnc.py              # moddingflaeche-tnc.md   (~4 min)
python tools/probe_audio.py             # audio.md        (~70 s)
python tools/probe_ui_assets.py         # ui-assets.md
python tools/probe_vtpages.py selftest  # virtualtextures.md
python tools/probe_texdb.py             # texdb.md
python tools/probe_idcl.py              # IDCL-Derivation
python tools/probe_loadpaths.py --self-test   # ladepfade.md
python tools/probe_savegame.py          # spielstaende.md

probe_loadpaths.py --self-test also checks the negative findings. If it fails after a game update, the affected document is outdated — this applies generally to all verification tools here.
