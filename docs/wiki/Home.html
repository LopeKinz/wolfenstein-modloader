In plain wordsIn einfachen Worten

The start page of the wiki covers Wolfenstein: The New Order and Wolfenstein II: The New Colossus. It opens with a 'Start here' table that sends players to the WolfSDK Loader guide, modders to the Studio guide, and everyone to the FAQ and the mod.json format, in English and German, plus the download of WolfSDK 0.3.0. It explains the three levels of proof: measured in the running game, inferred from the program file, or only a text string found in the file. A big table shows what currently works, what does not, and what is still unverified for each game.

  • Strict rule: a text found in the game program does not prove the feature exists; of 2,231 harvested setting names in Wolfenstein II, 409 were not settings at all.
  • The New Order: patched archives load in game (14/14 rebuilt files, 48 minutes of play, 0 errors); cheat settings from config files stay locked, while the console (Ctrl+^) is code-read only and untested.
  • Wolfenstein II: value edits (pistol magazine 10 to 30), a custom weapon skin, a custom map and maps loaded from the developer menu are confirmed in a running game.
  • Wolfenstein II: the encrypted config files were cracked and used to run God mode and infinite ammo in a real save; sound and video replacement in the Studio (0.3.0) is not yet tried in game.
  • Still not working or unverified: The New Order's new 3D models and megatexture pixels, Wolfenstein II's megatexture pixels and loose files.

Documentation — Getting Started

This wiki describes two games and a tool:

  • Wolfenstein: The New Order (id Tech 5, WolfNewOrder_x64.exe) — the loader reads, patches, and launches this game.
  • Wolfenstein II: The New Colossus (id Tech 6, NewColossus_x64vk.exe) — the loader locates and launches it, passing Cvars, and writes its archives too: wolfsdk/tncpatch.py patches its IDCL containers directly (wolfsdk/game.py, TITLES["tnc"].mods = True for both titles). Decl value edits, a BC1 weapon skin, and a full dlc_0-precedence custom map have all been confirmed working in a real, running game — see the tables below and TNC Modding Surface.

The apps are described on WolfSDK Loader and WolfSDK Studio; their source and README are in the repository folder modloader/. The pages below contain what has been discovered about the games.

Keywords: documentation, research, overview, The New Order, The New Colossus, id Tech 5, id Tech 6, Dokumentation, Forschung

The Most Important Rule: Measured ≠ Speculated

This project is only as valuable as you can trust your claims. Therefore, the documents define three levels of proof, most sharply formulated in Asset-Loading-Paths.md:

Grade Means Example
Measured / RUNTIME In the log of a running game, on the disc, or proven via a run with real data. WARNING: com_allowConsole CANNOT be set in retail! in qconsole.log
Inferred / CVAR Read from the binary; the Name↔Meaning mapping is guessed via neighborhood. The .text of both games is SteamStub-encrypted, there is no call site as proof. fs_overlaypath — "Extra location for game files (with precedence over fs_basepath)"
Speculated / STRING The text exists in the binary, nothing more. A dead code path looks just as good. FSPATH_OVERLAY as an RTTI name

Keywords: evidence, proof, measured, inferred, speculated, evidence grades, Beleg, gemessen

Strings Are Not Proof: the Cvar Example

A string in the EXE does not prove that the function exists. How large the difference is: of 2231 "Cvar names" harvested as strings from Part 2, 409 are not Cvars at all, and 1433 real Cvars were missed. The engine's own registry holds 3,256, of which 304 are exposed to the retail console (TNC-CVar-Catalog.md, TNC-CVar-Validation.md).

For the game launched so far, almost nothing has been done. By far the largest part of all statements about Effect is unverified; statements about Format are mostly not.

Keywords: strings, cvar names, registry, exposed cvars, unverified, effect vs format

Before you believe anything stated here

These documents were created side-by-side in a short time and contradicted each other at 20 places. Raised in Known-Contradictions.md, processed on 21.09.2026: 17 were fixed in the text, 3 remain open with justification — two of which are embedded in the code and belong to other workers.

In case of a conflict, the rule remains: the newer, more detailed individual investigation overrides the older summary — and both override the README.

Keywords: contradictions, which document is right, newer overrides older, Widersprüche

Corrections That Changed the Direction of a Statement

So that no one falls back to an old status:

  • The Patcher does not hang onto the file end but writes into the slot; File-Formats.md §3 described up to that point the procedure, which demonstrably leads to a crash (W4).
  • A BIM Encoder exists (wolfsdk/image.py, only RGBA8) — six places explained it as missing (W5).
  • The IDCL Container (Part 2) and the .pages Container (Virtual Textures) are read, not "unsolved" (W8, W9).
  • The 2231 Cvars for Part 2 are candidates; 222 of them are among the 304 exposed Cvars (W3). Against the full registry of 3,256: 1822 are real, 409 are not Cvars.
  • The Slot space is exactly csize, not csize + 15 (W6).

Keywords: corrections, slot write, BIM encoder, IDCL, pages container, csize

Recalculate Evidence

Every document names the tool from which its numbers originate. All are purely read-only and do not start a game. They live in the research workspace: they are not part of the public modloader/ folder or the public packages.

python tools/verify_all.py              # all harmless checks
python tools/survey_engine.py           # engine-surface.md
python tools/survey_modding_surface.py  # moddingflaeche-tno.md
python tools/survey_tnc.py              # moddingflaeche-tnc.md   (~4 min)
python tools/probe_audio.py             # audio.md        (~70 s)
python tools/probe_ui_assets.py         # ui-assets.md
python tools/probe_vtpages.py selftest  # virtualtextures.md
python tools/probe_texdb.py             # texdb.md
python tools/probe_idcl.py              # IDCL-Derivation
python tools/probe_loadpaths.py --self-test   # ladepfade.md
python tools/probe_savegame.py          # spielstaende.md

Keywords: verification tools, probe, survey, recalculate, reproduce
