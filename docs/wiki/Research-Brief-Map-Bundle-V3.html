Research brief: Map Bundle V3

OpenOffen Original page in the GitHub wikiOriginalseite im GitHub-Wiki

In plain wordsIn einfachen Worten

This is an assignment, not a result. For Wolfenstein II: The New Colossus, it asks a worker to check a custom map bundle based on the DLC map c2v1 and to build a complete, self-contained copy under a new map name with one small visible entity change. It stresses that simply copying a retail archive and adding a new map name is not a real custom map. It also demands clear separation between 'structurally valid', 'mounts', 'loads' and 'playable', and no writing to the live game.

  • Goal: a full dependency check of all map assets and a complete alias candidate.
  • The original retail map must still work after adding the alias.
  • Every important claim needs a negative check.
  • Limits for collision, navigation and rendering must be reported.
  • If the formats are not understood well enough, the worker should report the exact obstacle instead of shipping a misleading bundle.

Dies ist ein Auftrag, kein Ergebnis. Für Wolfenstein II: The New Colossus soll ein Bearbeiter ein eigenes Kartenpaket auf Basis der DLC-Karte c2v1 prüfen und eine vollständige, eigenständige Kopie unter neuem Kartennamen mit einer kleinen sichtbaren Objekt-Änderung bauen. Er betont, dass ein kopiertes Originalarchiv mit neuem Kartennamen noch keine echte eigene Karte ist. Außerdem verlangt er eine klare Trennung zwischen „strukturell gültig“, „eingebunden“, „geladen“ und „spielbar“ und keine Schreibzugriffe auf das installierte Spiel.

  • Ziel: eine vollständige Abhängigkeitsprüfung aller Karten-Assets und ein vollständiger Alias-Kandidat.
  • Die Originalkarte muss nach dem Hinzufügen des Alias weiter funktionieren.
  • Jede wichtige Aussage braucht eine Gegenprobe.
  • Grenzen bei Kollision, Navigation und Darstellung müssen benannt werden.
  • Sind die Formate nicht gut genug verstanden, soll der Bearbeiter das genaue Hindernis melden statt ein irreführendes Paket zu liefern.

Technical detailsTechnische Details

Der technische Teil ist auf Englisch – so, wie er im Wiki steht. Unterstrichene Begriffe haben eine Erklärung auf Deutsch.

Worker w-map_bundle_v3-a1; task map_bundle_v3; research/implement. Read .agent-cache/WORKER.md. Bus %USERPROFILE%/.agents/skills/agent-cache-orchestrator/scripts/acbus.py.

Objective

Audit custom map bundle and produce a defensible isolated complete alias candidate plus a small authored entity change if formats permit. Need exact asset identity/dependency evidence; a copied retail archive plus alias mapspec is not a custom map.

Verification behavior

Every important assurance needs a counterexample/negative check. Distinguish static structural validity, mount, load, and playable geometry. Do not claim success from process/menu or string count. Report failures clearly.

Sources

tools/build_tnc_custom_map_prototype.py, tools/install_tnc_custom_map_full.py, tools/check_tnc_map_identity.py, wolfsdk/idcl.py, tools/entities.py, docs/tnc_custom_map_status.md, re_probes/agent_reports/small_custom_map.md, texdb_rewrite.md. Game /steamapps/common/Wolfenstein.II.The.New.Colossus dlc/dlc_2/base/chunk_22.resources (c2v1). Read existing resources metadata and map/entity formats first. Existing live dlc4 archive keeps original names, alias-only mapspec.

Ownership

New tools/build_tnc_map_alias_v3.py, tools/verify_tnc_map_alias_v3.py; new re_probes/map_alias_v3 directory and re_probes/agent_reports/map_bundle_v3.md. Do not edit earlier tools; propose master fixes as needed.

Forbidden

No writes to live game or saves, no launches/memory writes. No full retail asset duplication unless needed; use existing archive read-only. Do not modify hardlinked payloads. No changes outside ownership.

Acceptance

Audit all mandatory map assets and internal references. Full dependency closure retained in candidate, metadata integrity checked, original retail map remains resolvable if adding alias. Clearly define new map ID and visibly distinguish authored change. Report collision/navigation/rendering limitations. Only build if understood enough; otherwise provide exact format obstacle and evidence, not a misleading bundle.

Coordination/deliverable

Checkpoint significant milestones; publish useful facts. Concise outcome, files, checks, remaining blockers. Master owns runtime loading research in parallel. Finish bus task; master verifies result.
