Research Task: Map/DLC Selection Logic

OpenOffen Original page in the GitHub wikiOriginalseite im GitHub-Wiki

In plain wordsIn einfachen Worten

Task description for Wolfenstein II (TNC): when a base map and a DLC map share the same name, which one does the game choose? The worker should find out, by reading files, logs and code only, whether chunk references, layer settings or save data decide this. An earlier real priority test failed because of a hash check or a start command that did not run.

  • The original DLCs use chunk numbers 20, 22 and 24.
  • The game does find a custom dlc_4 entry for map c02p0.
  • Static research only: no game starts and no changes to the installation.
  • Goal: clear conditions for one decisive test run.

Aufgabenbeschreibung zu Wolfenstein II (TNC): Wenn eine Basis-Karte und eine DLC-Karte denselben Namen tragen, welche wählt das Spiel? Der Worker soll nur durch Lesen von Dateien, Logs und Code klären, ob Chunk-Verweise, Layer-Einstellungen oder Spielstanddaten darüber entscheiden. Ein früherer echter Vorrang-Test scheiterte an einer Hash-Prüfung oder an einem Startbefehl, der nicht ausgeführt wurde.

  • Die Original-DLCs nutzen die Chunk-Nummern 20, 22 und 24.
  • Das Spiel findet einen eigenen dlc_4-Eintrag für die Karte c02p0.
  • Nur statische Untersuchung: kein Spielstart und keine Änderungen an der Installation.
  • Ziel: klare Bedingungen für einen einzigen entscheidenden Testlauf.

Technical detailsTechnische Details

Der technische Teil ist auf Englisch – so, wie er im Wiki steht. Unterstrichene Begriffe haben eine Erklärung auf Deutsch.

Goal: Investigate how TNC decides between Base and DLC Mapspecs when they share the same map name, and determine whether Savegame/Map metadata determines selection before the container mount.

Context: Retail DLCs primarily use chunkid 20/22/24; the custom dlc_4 spec for c02p0 is found. The Canary container is structurally valid, but the final real priority test failed due to the +0x08 Hash Gate or the unexecuted start command.

Scope: Read statically only: all Retail and Probe packagemapspec.json, Savegame game.details/checkpoint_mapstart.dat, Logs, Parser code, and existing Reports. No game starts, no installation changes.

Acceptance Criteria: Clear decision conditions for a single run, including an indication of whether refchunks/layer/basechunkid or Savegame data influences priority. Report exclusively to re_probes/agent_reports/map_selection.md.
