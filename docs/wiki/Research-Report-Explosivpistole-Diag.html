Explosive Pistol Does Not Explode: Diagnosis

Partly solvedTeilweise gelöst Original page in the GitHub wikiOriginalseite im GitHub-Wiki

In plain wordsIn einfachen Worten

A mod for Wolfenstein II: The New Colossus was meant to make the pistol fire exploding rockets. The larger magazine worked, but the shots did not explode. Reading the game code points to the load order: the pistol is loaded before the rocket it inherits from, so it silently copies an empty parent and stays a normal gun. The report proposes a fix that points the ammo to the rocket directly instead, but this fix has not been tested in the game yet.

  • The pistol is the only 1 of 299 inheriting entries listed before its parent in the preload list.
  • The game does not reload the parent later and gives no warning, so the rocket settings are lost.
  • Other causes were checked and ruled out, e.g. a second copy of the pistol or an outdated hash.
  • Recommended fix: set the ammo's projectile to the rocket, as the retail throwing hatchet does.
  • A weaker second cause (the weapon class only fires instant hits) is only ruled out by an in-game test.

Status as of 2026-09-26. All information is read-only: Live archives under D:/.../Wolfenstein.II.The.New.Colossus, runtime snapshot re_probes/runtime_87400/module.bin (disassembled with tools/tnc_runtime_code.py). Nothing written under D:/SteamLibrary or Saved Games, no project file other than this report.

User Finding: The magazine shows 30 rounds. Therefore, the Decl route from tncpatch reaches the game (ammo clipSize or Upgrade valueInt, both set to 30). The pistol still does not explode. Tested on the Kit map (dlc_0, c2v1).

Result

Cause 1 (High Probability): The loading order breaks the new inheritance. projectile/player/pistol appears in the preload list before its new parent projectile/player/kampf_pistol_rocket. The engine places all entries "deferred" first and then loads them sequentially. When the pistol is parsed, inherit finds the rocket object already created but not yet loaded. The loader does not load it within this nesting. The parser copies the empty parent without warning. The pistol is thus "Class standard values + own edit block", remaining a hitscan weapon without splashDamageDecl. The ammunition change takes effect because it resides in its own edit block and its parent base_ammo is loaded beforehand.

Proven are the code path and the data state. It has been established that the path is traversed exactly as described at runtime and that an unloaded Decl object carries only class default values. Side effect, if this holds: The pistol also loses everything from projectile/player/default (recoil weaponRecoilInfo, tracerMtr, spread).

Also applies to campaign maps: Init2 (0xABD340) loads init at startup and then common (0xABD442, 0xABD520). Pistol, ammo, upgrade, and the entire rocket chain are listed in common.mapresources with the Immer bit. The pistol is thus broken from game start on every map equally.

Cause 2 (low confidence): The standard weapon class only fires hitscan. This contradicts the retail throwing hatchet: weapon/player/sp/hatchet inherits like handgun_nomesh from base_nomesh, has no inventoryClass, and fires via ammo.projectileDecl = projectile/player/axe_throw an Entity projectile. This is documented by the data, not by own runtime measurement. Only a test with the fixed Cause 1 rules it out.

Cause 3 (only important for the fix): Upgrades swap the projectile. With silencer or elephant rounds, the weapon fires pistol_silenced, pistol_elephant, or pistol_elephantrounds_silenced. Under Cause 1, these are also broken because they inherit from the pistol. A fix via ammo must bend them.

Excluded (measured)

  • Other copies and priority: All 30 .resources scanned (base, patch_1..4 including chunkbase, all chunks, dlc_0/1/2/3/5, also our chunk_22), every type, name containing player/pistol or handgun. projectile/player/pistol and ammo/player/sp/handgun exist exactly once each (gameresources), weapons/handgun/magazine_size twice (gameresources, patch_3). All copies are unpacked and carry the mod text. There is no compiled or binary second form.
  • data_hash +0x50: Exactly the 4 modified entries have an outdated hash (all remaining hits match). This is checked only via resourceStorage_checkDataCheckSum (live 0), and a failure would be a FatalError. The ammo change with an equally outdated hash came through.
  • Rocket chain not preloaded: kampf_pistol_rocket, projectile_ent/kampf_grenade_rocket, damage/player/kampf_grenade, and fx weapons/kampf/rocket are listed with ALWAYS in common and the c2v1 manifest.
  • Console command for inspection: listDecls, printDecl, and reloadDecls are registered but not among the 34 exposed commands (cmdtable.md). The console cannot display the Decl. The error path also does not write a warning, so dumpWarnings does not help.

Fix for Cause 1

Recommended (fits everywhere in place, no rebuild needed): Swap projectile via reference instead of via inherit. References may point forward: Retail has 3 such cases (upgrade valueDecl → later listed weapon, e.g., battlerifle/marksman), and they work. This is exactly the throwing hatchet pattern.

Asset Change new / space
projectile:projectile/player/pistol Remove entry from mod.json (back to Retail) –
ammo:ammo/player/sp/handgun edit.projectileDecl = projectile/player/kampf_pistol_rocket (+ clipSize 30) 482 / 512 B
upgrade:weapons/handgun/silencer edit.modifiersData.item[0].data.valueDecl = Rocket 635 / 640 B
upgrade:weapons/handgun/elephantrounds as file: patch_2-Retail text with valueDecl = Rocket (a set would take the DMT_UPGRADE_ANIM from the patch_2 copy) 701 / 704 B in both copies
upgrade:weapons/handgun/elephantrounds_silencer edit.modifiersData.item[0].data.valueDecl = Rocket 483 / 1216 B

Cost: The pistol adopts the thrower's firing sound, direct hit damage, and recoil. The silencer no longer makes it silent. This works on all maps.

Alternative (retains pistol sound and damage): inherit remains projectile/player/default, and the rocket fields are placed directly into the pistol's edit block (hitscan = false, notHitscanInfo{…}, splashDamageDecl, fxDecl, …). The silencer and elephant variants then inherit these. This totals 534 B (only what is necessary) or 786 B (everything) versus 448 B of space.

This means building new gameresources and a 702 MB backup on D:.

Not recommended: reordering the lines in common.mapresources (5 copies, global preload list, no asset type in the loader).

Inspector gap: tools/verify_weapon_mod.py checks if the parent is preloaded, but not if it comes before the child. This specific rule (parent line < child line in the highest common copy) would have reported this error as the sole violation under 299.

Test in-game (after fix)

  1. Restart the loader, apply the explosive pistol (new version), and start the game.
  2. Shoot at a wall with the pistol from more than 10 m distance. The rocket bounces off at approximately 5 m and ignites only after 3 s.

If it explodes, causes 1 and 2 are resolved: identical rocket Decl, but without inherit. If it does not explode, it is due to the weapon class (cause 2).

Without a new version, immediately in the current state: Does the pistol have almost no recoil or no tracer? Then it is also missing its parent default. This fits cause 1, but is only a soft indicator.
