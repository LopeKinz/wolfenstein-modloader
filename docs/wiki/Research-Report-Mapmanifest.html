In plain wordsIn einfachen Worten

When you add a new object to a map in Wolfenstein II: The New Colossus, which of the map's many data files must know about it? This report found that only the .mapresources list needs one line per resource, and even that is only a preload hint, because the engine loads missing assets on first use. Precomputed data like texture streaming, visibility, baked shadows and the AI navmesh does not need changes and cannot be rebuilt anyway. All of this comes from the code and files; nothing is confirmed at runtime.

  • The .mapresources reader and writer round-trips 129 of 129 manifest copies byte-exactly and rejects 12 of 12 broken variants.
  • Six runtime load counters from real game logs are reproduced exactly from the manifests.
  • A new asset needs +1 manifest line (optional) plus an entity that places it; nothing else must change.
  • Consequence: new geometry casts no baked shadows, blocks no visibility and is not walkable ground for enemies.
  • Gap: no tool yet adds a new entry to an existing archive container.

Result in one sentence

A new asset requires exactly one manifest line per resource at the map level (and even that is just a preload, not a permission). Stream-Tree, Modelstream, PVS/Tome, Static-Shadows, and Navmesh are not touched. All five are precalculated and only reusable. Any path accepts an object that does not appear in them; this is documented by code but unverified at runtime.

1. .mapresources – Format and Round-Trip

MRL v1, read from 0xABFE30 and called from idResourceManagerLocal::LoadNamedResourceBlock (0xAC1730), which opens generated/buildGame/%s.mapResources via idResourceList::Load (0xABA110):

'MRL\x01' | vec<str> layers | vec<u32> default_layers | vec<{str, vec<u32>}> groups
| vec<str> types | u32 n, n × (u32 type, str name, u8[24] mask) | vec<str> maps

A line remains valid if mask & active != 0 holds (0xAC070D..0xAC0726). 0xAC047C sets bit 191 unconditionally, so the mask 00×23 + 80 means "always load". In the 41 effective manifests, 629,035 of 787,053 lines have exactly this mask; 158,018 have only layer bits, neither. Zero lines have string bits.

The read copy is the one with the highest patch level. This proves select: The lowest copy matches the counter states in none of the 6 cases.

2. Is the Manifest the Definitive List? No, It's a Preload List.

  • Code: Load (0xABA110) searches for the name (0xAB8F80). If missing, the function creates and loads the resource (vtable +0xC8, +0x28). The only brake is resource_errorInGame: 1 = Warning (0xABA419), 2 = FatalError (0xABA446). The live value in the running game is 0, default "0", description "0 - Nothing. 1 - Warning. 2 - Fatal Error - if loaded during gameplay" (idCVar at 0x2F53F70, name at +0x18).
  • Convention: Each of the 17 Retail map chunks lists 100% of its entries (144,713 entries, 0 unlisted). The counter sample gameresources shows 37,790 unlisted entries, so the check can fail.
  • Cross-container: 612,969 of 786,228 resolvable manifest lines exist only outside the chunk of the map. The name is resolved across all mounted containers, so the new asset may reside in its own container.
  • 825 Retail lines name resources that do not exist in any container (anim 713, image 90, model 20, cm 2). One line before its payload is thus Retail practice.

Follow-up for new geometry: It occludes nothing (no Occluder), is not in static shadows, and is not ground for the AI. Obstacles can only be handled via the runtime cutter. Therefore, it belongs where these three things do not interfere.

4. THE RESULT: minimal change amount for a new asset

  1. Payload under exactly the name the Entity forms (e.g., models/wolfsdk/box.lwo$static_instance=1$lodgroup=default, see meshfmt), in any mounted container. Gap: No tool adds a new entry to an existing IDCL container (idcl.rebuild replaces only). tools/dlcmod.baue_archiv builds a new container without dependency records; whether models load without Dep-Records is open.
  2. Manifest: +1 line per resource, mask 000…0080, in the copy with highest priority: python tools/probe_mapmanifest.py author --source re_probes/idclwriter/chunk_22.resources \ --map game/dlc/c02/c2v1_custom \ --type model --name 'models/wolfsdk/box.lwo$static_instance=1$lodgroup=default' \ --type cm --name 'models/wolfsdk/box.lwo$filterclip=18$simplify=20$filteroccluders=true' \ --out re_probes/mapmanifest/c2v1_custom_plus2.mapresources \ --container re_probes/mapmanifest/c2v1_custom_plus2/base/chunk_22.resources Result: 7/7 Manifest checks (old lines unchanged, header byte-identical, preload count +2), 4/4 Container checks. Independently verified: probe_datahash 7127/7127, probe_idclhash +0x08/+0x20 OK. Exactly 1 data hash moved, 0 Dep-Records. The cm name format comes from the corpus (1,217 cm lines under models/ in c2v1) and must be confirmed by cmfmt.
  3. Entity that places the asset (entitypipe). Without it, nothing loads, because the manifest places nothing.
  4. Not needed: modelstream, staticStreamTree, pvs, tome, bshadows, hknavmesh.

Point 2 is strictly optional: Without the line, Load loads the asset on first reference, silently with errorInGame=0. With the line, it preloads when loading the map, just as Retail does to 100%.

5. What cannot be shown offline

"Listed" does not mean "loaded at runtime". Everything above is structurally valid after these checks, runtime unconfirmed. This applies particularly to behavior without a Stream-Tree entry, without static shadows, with PVS −1, and for Navmesh-Cutting on an idStaticInstanceEntity. The container c2v1_custom_plus2 references a box whose payload is not yet in any container (Point 1). It is a mechanic proof, not a test candidate.

6. Corrections to a1

  • "PVS stale → nothing gets culled": not substantiated. Only PVS=NULL and −1 from queries are substantiated.
  • "Skipping very large static shadows" makes missing bshadows non-critical: incorrectly justified. This is a console hack (r_discardLargeStatShadowsAtLoadHack, live −1 = on PC off). Missing bshadows are non-critical due to the NULL-test in 0x382036.
  • global_resolution.json was an outdated duplicate of resolve.json and has been deleted.
