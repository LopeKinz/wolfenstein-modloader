Research brief: Save Integrity V3

OpenOffen Original page in the GitHub wikiOriginalseite im GitHub-Wiki

In plain wordsIn einfachen Worten

This is the assignment given to a research worker, not a result. Save game candidates for a custom map in Wolfenstein II: The New Colossus were malformed, and earlier explanations were only hypotheses. The worker must parse original and candidate files to find the concrete structural errors, fix the candidate builder and, if possible, work out the checksum in game.details. Correct 4-byte hashes alone must not be taken as proof that a save is valid.

  • Suspected issue: the builder replaces map names but may leave old length values in place.
  • The game.details checksum should be tested against several original files, not just one sample.
  • Rebuilding an unchanged save must give byte-identical files; longer and shorter names must also work.
  • Deliberately wrong length values and checksums must be rejected by the checks.
  • No writing to real saves, no game launch, and no claim that the map is playable.

Objective

Determine the exact cause of our malformed custom-map save candidates offline. Fix the candidate builder and derive game.details checksum if possible. Prior reports are hypotheses, not trustworthy runtime proof.

Verification behavior

For every important assurance provide a negative counterexample. Report uncertainty and failed hypotheses explicitly. Correct DAT hashes alone do not imply a structurally valid save. Do not conclude verify files block saves from AES strings or unknown checksum alone.

Sources

  • tools/build_custom_save_candidate.py (currently replaces NUL strings in mapstart, but length prefixes may remain stale; checkpoint special case duplicated).
  • re_probes/save_backups/SLOT0_before_c2custom (original FC2-WOLF0)
  • re_probes/custom_save_candidates/FC2-WOLF0-c2v1_custom_v2
  • tools/probe_savegame.py, tools/savehash.py, docs/spielstaende.md
  • public primary id Software Doom3/BFG idDict::Checksum source: test dictionary checksum algorithms against multiple distinct original game.details. Browse when using external sources.

Ownership

tools/build_custom_save_candidate.py; new tools/probe_details_checksum.py; new tools/verify_custom_save_candidate.py; re_probes/agent_reports/save_integrity_v3.md; new isolated candidate under re_probes/custom_save_candidates/v3.

Forbidden

No live save writes, game install writes, launches, process memory modifications, or claims of playable map. No broad test suites. Other docs and source belong to master.

Acceptance

Find concrete structural errors by parsing actual original/candidate files; preserve untouched structures; candidate identity transform should be byte-exact for relevant DAT/details; longer/shorter names must round-trip; deliberate malformed prefixes/checksum rejected. Check game.details checksum on corpus if solved, not one sample. If not solved, clearly mark candidate invalid/unverified.

Coordination and deliverable

Checkpoint meaningful milestones, publish proven cross-worker findings, return concise findings and artifacts. Finish bus task when work done, master verifies. Real token metrics only if available.
