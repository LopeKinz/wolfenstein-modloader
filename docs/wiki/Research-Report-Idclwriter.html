In plain wordsIn einfachen Worten

Wolfenstein II (TNC) archives carry four kinds of hash fingerprints that must match their contents. This report adds a writer that recalculates all four in the right order. It rewrites three original archives byte-for-byte identical, and it repairs a custom map bundle whose four new files still carried old fingerprints, which could crash the game when a checking setting is on, without changing any data.

  • 3 of 3 original archives rewritten byte-identical, from 401 KB to 97 MB.
  • Repaired bundle: 7,127 of 7,127 checkable entries now correct (was 7,123).
  • All 7,128 file contents stay identical; only 6 table fields and 2 header fields changed.
  • 6 of 6 deliberate error tests are caught.
  • One entry per container with a special compression mode cannot be checked.

Die Archive von Wolfenstein II (TNC) tragen vier Arten von Hash-Fingerabdrücken, die zum Inhalt passen müssen. Dieser Bericht ergänzt ein Schreibwerkzeug, das alle vier in der richtigen Reihenfolge neu berechnet. Es schreibt drei Original-Archive byte-genau identisch zurück und repariert ein eigenes Karten-Paket, dessen vier neue Dateien noch alte Fingerabdrücke trugen, was bei aktivierter Prüfeinstellung das Spiel abstürzen lassen könnte, ohne dabei Daten zu verändern.

  • 3 von 3 Original-Archiven byte-gleich neu geschrieben, von 401 KB bis 97 MB.
  • Repariertes Paket: 7.127 von 7.127 prüfbaren Einträgen jetzt korrekt (vorher 7.123).
  • Alle 7.128 Dateiinhalte bleiben identisch; nur 6 Tabellenfelder und 2 Kopffelder ändern sich.
  • 6 von 6 absichtlichen Fehlertests werden erkannt.
  • Ein Eintrag pro Container mit einem Sonder-Kompressionsmodus lässt sich nicht prüfen.

Result in one sentence

The Writer writes three Retail containers byte-for-byte identical and recalculates all four hashes during this process; the defective Bundle container of the other Master session is repaired and drops from 7123/7127 to 7127/7127 without a single Payload byte changing.

Exactly the four Payloads generated by the Bundle itself, exactly as described in the order. They carry the +0x50 of their template. With resourceStorage_checkDataCheckSum set to the default 0, no one reads it; with 1, it is a FatalError -- a latent crash, not a cosmetic error.

re_probes/map_alias_v3/ was only read. The repaired container lies in re_probes/idclwriter/chunk_22.resources.

2. The Writer

wolfsdk/idclwrite.py, stdlib plus the existing Oodle integration. No compressor added -- it is not needed for this repair either, see Section 5.

Function Purpose
finalize(path, oo, data=True) Recalculate the four hashes at the container in situ. Writes only the first addr_data bytes.
write(archive, dest, changes, oo) idcl.Archive.rebuild() plus finalize(). With empty changes, the Round-Trip.
repair(src, dest, oo) Copy and finalize() -- for containers whose Payloads match but whose Hashes do not.
stale_data_hashes(path, oo) The check that the Engine makes with a set CVar, as a library call.
stale_dep_hashes(archive) Dependency records holding a +0x60 that no local entry carries anymore.
hash60_rule(alt50, alt60, neu50) What becomes of +0x60 -- see Section 4.

The order is the only one that works, and it is documented in the module:

  1. Entry +0x50 = MurmurHash64B(decompressed Payload, Seed 0xDEADBEEF), length from usize at +0x48.
  2. Entry +0x60 according to the rule from Section 4, then follow dep+0x18.
  3. Header +0x20 = FarmHash64 over the metadata +0x78 up to and including the IDCL marker -- contains entry and dependency tables, so must wait until (1) and (2) are done.
  4. Header +0x08 over the finished header. +0x20 lies within header[0x10:0x78], therefore last.

The hash implementations are imported from tools/probe_datahash.py and tools/probe_idclhash.py, not rewritten: an implementation of a carrying hash, not two that can diverge.

3. The Round-Trip -- the Carrying Control

python tools/probe_idclwriter.py --roundtrip. Read Retail, write unchanged back, compare bytes. This can fail in two independent ways: the layout can deviate, and every newly calculated hash must land on the value that the delivered file already carries.

Archive Bytes Entries Newly Calculated Result
patch_4_chunkbase_6.resources 401 255 25 25 identical
chunk_8.resources 27 861 331 1 562 1 562 identical
chunk_16.resources 97 392 281 2 867 2 866 (1x Mode 4) identical

3/3 byte-identical, with 4,453 of 4,454 entry data hashes plus 3x +0x20 and 3x +0x08 recalculated and exactly matched. SHA256 of the sources (and thus the outputs):

The driver additionally checks that finalize() moves nothing in an unchanged file (data_hash/hash_0x60/deps all 0) -- otherwise an identical file with secretly shifted fields would be visible. The copies are deleted after comparison; a byte-identical second build of 125 MB Retail adds nothing that the digest does not already state (--keep preserves them).

4. Two Measurement Corrections in the Docstring of wolfsdk/idcl.py

Both concern assumptions on which the Writer must act, so they are measured here rather than copied.

(a) +0x60 also deviates for type cm. The docstring lists image/extkisclule/cfile/compfile. Across four archives (chunk_8, chunk_16, gameresources, Retail-chunk_22, 62,293 entries), an additional 21 cm entries deviate (gameresources 16, chunk_22 5). The Writer therefore ignores the type entirely: +0x60 follows +0x50 only where it was already equal to it beforehand, and otherwise stops. This is a No-Op by construction on an unchanged container -- precisely what causes the Round-Trip to fail.

(b) dep+0x18 applies only to the 64-bit Records of the +0x60 mirror. The statement "the same value must be in dep+0x18 of every Record that references the entry" holds for Records that carry a 64-bit value at all -- all 233 locally resolvable skeleton references in gameresources match it. It does not hold generally:

Archive locally resolvable, dep_type=2 carries +0x60 does not carry it
gameresources 3,741 233 3,508
chunk_8 26 3 23
Retail-chunk_22 290 5 285

The 3,508 are material/renderParm/sound and carry 32-bit values unrelated to +0x60 and never had them. All dep_type=5 Records (11,545 in gameresources, 1,214 in chunk_22) are rs_emb_sfile with names of the form image#path.tga$mtl and resolve to no entry of the archive. Propagating solely over (Type, Name) would thus destroy these Records. The Writer updates only Records that actually carried the old value. Changes to +0x60 on a (Type, Name) shared by multiple entries (860 renderProgResource pairs per archive) are not propagated at all: which entry is meant cannot be determined, and guessing writes an incorrect hash into foreign Records. In chunk_22 there are 0 such pairs.

sha256 Source 95236c3ebcaffb73a0f367bedbec71b720537677c3ab2aa3d87bd8cafd5fe2c2 sha256 repaired b41f25135bd3374e594a7c37fe9896d9f66966c75351340b15bd76891bb945f4 151 702 019 Bytes, unchanged

No compressor is involved. The four payloads are already what they should be -- the only error was the hash above them. The repair copies the file and rewrites exclusively the header and table entries. The question "can the original codec be reproduced" does not arise for this container; idcl.pack_payload (Oodle-DLL) is used only when a caller passes changes, which here happens only in Control 3 on a disposable copy.

7. What Remains Open

  • One entry per container with compression mode 4 remains unchecked. In chunk_22 this is staticShadowGeom:maps/game/dlc/c02/c2v2/_combo/_world.bshadows (usize 29 227 487). For the 12-byte prefix there is no decoder, so its +0x50 cannot be recomputed or verified. It comes unchanged from the Retail Archive and is therefore presumably correct, but that is a conclusion, not a measurement. With the set Cvar it is the only entry of the container for which this work makes no statement. finalize() leaves it intentionally in place, rather than guessing.
  • +0x60 for image/cm/cfile/compfile/extkisclule remains underived. The Writer conserves the value. For a newly invented entry of these types there is thus no correct +0x60 -- it is checked by no read code path, but whoever chooses it freely must keep dep+0x18 consistent themselves.
  • re_probes/idclwriter/ is excluded via .gitignore (re_probes/*). Intentionally not released: the content is a 151-MB binary artifact that is reproducible at any time from source plus tools.
  • The Round-Trip ran on 3 of 24 Retail Archives (401 KB to 97 MB). gameresources.resources (702 MB, 50 839 entries) was not round-tripped due to runtime reasons; the +0x60 and dep+0x18 collections from Section 4 include it instead.
