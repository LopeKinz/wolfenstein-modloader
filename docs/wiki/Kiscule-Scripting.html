In plain wordsIn einfachen Worten

Kiscule is the mission scripting system of Wolfenstein II (TNC): triggers, enemy waves, doors and audio are built as node graphs, like boxes connected by wires. The researchers decoded the file format completely and can read and write all 2,408 scripts back byte-for-byte identical. Modders can safely change numbers such as delays or trigger counts. Whether the game accepts rewritten scripts is not yet confirmed in the game.

  • 2,408 scripts with 70,274 nodes in 205 node types; every byte is explained.
  • Round-trip: 2,408 of 2,408 scripts written back identical, including compression.
  • All 205 node types match classes in the game program; 113 more exist but are never used.
  • 30 of 2,408 original scripts contain small defects, such as 43 connections that point nowhere.
  • All 2,443 map references to scripts resolve.

Technical detailsTechnische Details

Der technische Teil ist auf Englisch – so, wie er im Wiki steht. Unterstrichene Begriffe haben eine Erklärung auf Deutsch.

Kiscule is what drives the missions in Part 2: triggers, enemy waves, intermission sequences, doors, and audio. It is the id-tech-6 equivalent to the .script files from Part 1 — but not a text interpreter, rather a node graph, as drawn by an editor.

All numbers here are measured from the unmodified Retail installation under D:\SteamLibrary\steamapps\common\Wolfenstein.II.The.New.Colossus\base\ (read-only only). Reproducible with:

python tools/kiscule.py --dump        # Unpack 2408 scripts into cache
python tools/kiscule.py --roundtrip   # Write back bit-exactly, all 2408
python tools/kiscule.py --verify      # Counter-tests plus negative tests
python tools/kiscule.py --maplink     # Map <-> Script <-> Entity-Name
python tools/kiscule.py --signatures  # 205 node types with signature
python tools/kiscule.py --signature idKisculeNodeDelay
python tools/kiscule.py --graph gp_kiscule_devstarts

Underlying infrastructure: wolfsdk/idcl.py (Archive), wolfsdk/oodle.py (Kraken via game DLL), tools/extract_tnc.py (Unpack). --dump requires roughly one minute initially; thereafter everything works out of %TEMP%\kiscule-cache (13 MiB raw, 186 MiB text).

1. The Container: Two Layers, Both Active

extkisclule is one of three types that appear binary in the archive but are not. Behind the archive compression lies another layer:

0x00  i64  usize   >= 0: Length after unpacking. < 0: Raw text, |usize| long
0x08  u64  csize   always len(payload) - 16
0x10  ...          Kraken frame (starts with 0x8C) or just the raw text

Measured against all 2408 unique entries: 2393 Kraken, 15 raw.

The 15 "negative" ones are not an exception. d9ffffff… = −39 simply means: 39 bytes, uncompressed. And these 39 bytes are

\n\tedit = {\r\n\t\tkiscule = {\r\n\t\t}\r\n\t}\r\n}\0

— a empty Kiscule. Kraken does not make 39 bytes smaller, so the packer stores them raw. The rule raw if compressed >= raw reproduces exactly these 15 and no others (--roundtrip, 2408/2408).

The re-compression matches Retail bit-exactly. Kraken, Level 4 (Normal), via the game's own oo2core_5_win64.dll: 2408 of 2408 frames are byte-identical to what is in the archive. This allows rebuilding an unmodified script without any deviation — the prerequisite for a desired change being the only change.

Compression ratio across all scripts: 13,293,044 → 195,090,346 bytes, so 14.7 : 1.

2. The Text: A Line Grammar, Three Cases

The unpacked content is Decl plaintext, machine-generated, and therefore strictly regular. Each line is exactly one of three, indentation is always exactly one tab per nesting depth:

<tabs>key = {          Block start
<tabs>}                Block end  (at the depth of block contents minus one)
<tabs>key = value;      Scalar

Five value types, and no others: int, float, "string", true/false, NULL. Counted across all scripts: 3,026,083 int, 1,684,238 string, 682,207 bool, 12,820 float, 10,119 NULL.

Structure: The file begins with a newline, the root block has no own { line (its content is at depth 1, the closing } at depth 0), and at the very end stands a NUL byte. Line endings are either LF (1461 files) or CRLF (947) — never mixed.

Measured: 9,243,027 lines across 2408 files, 0 unparsable.

    edit = {
        kiscule = {
            version = 6;
            nodes = {
                num = 2;
                item[0] = {
                    name = "idKisculeNodeBeginGame";
                    id = 1276314557;
                    nodePos = { x = 180; y = 220; }
                    parameters = {
                        class = "idKisculeGraphNodeParametersBeginGame";
                        object = { ignoreInitialFlag = true; }
                    }
                    connectionPoints = {
                        num = 2;
                        item[0] = {
                            name = "OnBeginGame";
                            id = 821853744;
                            connections = { num = 0; }
                            type = "OutputNotification";
                            properties = 8;
                            visible = true;
                        }
                        …

(above condensed for readability; in the file each field stands on its own line)

Four blocks at top level, in this order, in every script: version, nodes, comments, variables.

  • version is 6 in 2329 scripts and 5 in 64. A structural difference between 5 and 6 is not visible in the data: same blocks, same fields, same node types. What the version means remains open. (In the 15 empty scripts version is missing entirely.)
  • comments are editor notes: name, id, pos, size, parameters (with fillColor, borderThickness, insideText …). 12,068 pieces. Purely cosmetic, but they stand in the file and belong to the roundtrip.
  • variables are named graph variables: 829 pieces, all with fields name, global, isCrossMap, defaultValue, value. Classes: idKisculeGraphVariableBool 433, …Int 229, …EntityReference 69, …Time 50, …Float 34, …ListEntityReference 12, …EntityDef 2. isCrossMap is the interesting switch: a variable that survives across map changes.

3. The Graph

3.1 Nodes

item[i] = {
    name = "idKisculeNodeDelay";     <- the node type
    id = 1276314557;                 <- unique within the file
    nodePos = { x; y; }              <- editor layout only
    parameters = { class; object; }  <- or  parameters = NULL;
    connectionPoints = { num; item[…]; }
}

70,274 nodes in 205 types, median 19 nodes per script, maximum 532 (civilians_kiscule_soldier_approach, 1.5 MiB text). 15 scripts are empty.

parameters = NULL; occurs — nodes without their own parameter object.

3.2 Connections

item[j] = {
    name = "Trigger";
    id = 315942819;                  <- unique within the file
    connections = { num; item[…]; }
    type = "InputRegular";
    properties = 8;
    visible = true;
}

Six type values. The numbers in this section come from a sample of every fourth script (602 of 2408, 155,538 connections) — the roundtrip and graph numbers in section 7 are instead full surveys.

type Count (sample 1/4) Direction
OutputVariable 41,501 out
OutputRegular 38,439 out
InputVariable 33,097 in
InputRegular 29,448 in
OutputNotification 13,049 out
InputEvent 4 in

Regular is flow control (a pulse), Variable is data flow (a value), Notification is an event output. Every parameter of a node appears additionally as InputVariable + OutputVariable of the same name — so a value can either stand inside the node or come from outside.

properties is a bitmask. Observed values: 8, 0, 24, 25, 9, 40, 1, 13, 16. What is measured:

  • Bit 16 (0x10) is set only on list connections. Of the 65,159 tested connections with a matching parameter: 9,280 carry Bit 16 and are lists; 55,487 do not carry it and are not — not a single exception. The reverse is not entirely true: 392 list connections do not carry Bit 16. Thus, the implication holds in only one direction.
  • Bit 8 (0x8) is the standard case for outputs and for InputRegular; InputVariable rarely carries it (27,691 × properties = 0).
  • The meaning of Bits 1, 4, and 32 is undetermined. They appear in 2,583 out of 155,538 connections (values 1, 9, 13, 25, 40). properties = 40 (8|32) exists only on OutputNotification.

The visible flag toggles display in the editor (142,645 true, 12,893 false) and correlates with nothing in the execution flow.

3.3 Edges

connections = {
    num = 1;
    item[0] = {
        name = "";
        id = 672289692;
        endNodeID = 1700766265;
        endConnectionPointID = 2126630981;
    }
}

Every edge exists at both ends. Of the 178,559 connection endpoints, 178,516 have a counterpart — that is 89,279 edges.

A guarantee that does not hold and which one easily derives incorrectly: the id of an edge is the same at both ends — in 149,620 cases, but in 28,896 it is not. Anyone who pairs edges via their id builds a parser that errs on every sixth case. The defining relationship is (endNodeID, endConnectionPointID), not the id.

43 connection endpoints in 29 Retail files point to nothing — to node or connection IDs that do not exist in the file. This is an error in the game data, not a parser error: --verify lists them individually. Affected are among others c01p1_gameplay_kiscule_choice, gp_kiscule_button1/3, c11p1_light_kiscule_1_*. A mod tool must account for this.

This is compounded by a file with duplicate connection IDs: sub_gp_c02p3/kiscules/gp023_kiscule_peanutbutter_event.decl — there, an EntityReference node carries its four connections twice, each pair with the same id. Of the eight, only one hangs from an edge. Also a defect in the game data. Together this makes 30 conspicuous files out of 2,408 (1.25%); the remaining 2,378 are consistent in every respect.

Roughly sorted by name, five groups emerge:

  • Notification — Event inputs from the game world: TriggerNotification, DamageNotification, UseNotification, VolumeNotification, AiKilledNotification, PickupNotification, AlarmNotification.
  • Action — anything that does something: ActionDamage, ActionTeleport, ActionAISpawn, ActionShowHide, ActionAutosave, ActionNextMap, ActionGiveItems, ActionMission.

  • Variable / Cast — Values: Bool, Int, Float, Str, Time, NamedVariable*, EntityToString, FloatsToVector.
  • Reference — Pointers to the map: EntityReference, ListEntityReference, PlayerEnt, ActiveAIList.

Cross-check against the EXE

docs/ghidra/rtti_tnc.json contains 683 RTTI classes with "Kiscule" in the name, of which 315 idKisculeNode* (excluding the …Parameters suffixes).

  • All 205 node types used in Retail have an RTTI class — 0 Unknowns. This is a prediction derived from two independent sources (game data, EXE) yielding the same result.
  • Three used types do not start with idKisculeNode*, but are instead named idKisculeLeverNotification, idKisculePlayerNotification, and idKisculePlayerControlledNotification.
  • 113 node classes exist in the EXE but appear in no Retail scripts. Among them: LogicGateAnd, LogicGateNot, LogicGateXor, TestBools, CompareBool, CompareString, ClampInt, ClampFloat, MultiplyInt, DivideInt, SquareRootFloat, ActionGiveUpgrades, ActionPlayerPerk, ActionPlayerManipulate, ActionShowScreen, ActionSetOrientation, HudTimer, VaultCheck, DoorNotification, NamedVariableStr, ListInt, ListString, ParameterListOperatorAddItem*. Fully verifiable against the RTTI list via --signatures. Whether the engine loads such a node when it is inserted remains untested — the game has not been run.

6. Map ↔ Script: The Rosetta Stone Holds

The connection is open. In the map:

entityDef c01p1_vo_kiscule {
    inherit = "kiscule";
    class = "idKisculeEntity";
    edit = {
        externalKisculeDecl = "maps/game/wolf/c01/c01p1_snd_vo/kiscules/c01p1_vo_kiscule.decl";
    }
}

python tools/kiscule.py --maplink checks both directions across all 29 maps:

29 Maps
externalKisculeDecl resolved: 2443/2443
EntityReference found in same map: 13520/13670 (98.90%)
  • 2443 of 2443 references point to a script that exists in the archive. (2443 is exactly the number of kiscule entities from docs/moddingflaeche-tnc.md — two independent counts, same number.)
  • 98.90% of idKisculeNodeEntityReference values are in the same map as entityDef <name> {. Thus, the entity name is the common key between map and script: whoever renames an entity in the map breaks the script, and whoever wants to know which script an object interacts with searches for its name.
  • The 150 failures are distributed across 29 maps; the top offender is volume_fire_damage_437646057 (21×). Whether these are runtime-spawned entities or map debris from the editor is undetermined.

The numbers in RETAIL (above in tools/kiscule.py) are hard-wired: a full sweep that deviates from this causes --verify to fail with return value 1. Whoever breaks the parser notices it here.

The predictions that had to be correct:

Claim Independent Recalculation Result
nodes.num is the node count item[0…num-1] must all exist, and no further ones may exist — in every num block of the file, including connectionPoints, connections, lists 2408/2408
70,274 nodes in 205 types survey_tnc.py --maps counts via regex over raw bytes, kiscule.py over the parsed tree identical
every node type is a real class RTTI from NewColossus_x64vk.exe 205/205
map references are resolvable externalKisculeDecl against archive contents 2443/2443
edges exist at both ends Mirror test over (endNodeID, endConnectionPointID) 178,516/178,559

All six lines are hard-coded as RETAIL in tools/kiscule.py and recalculated on every full sweep.

The Negative Test. A parser that reports everything green proves nothing. --verify therefore deliberately breaks one assurance and demands that the check succeed:

-- Negative test: tests must fail with corrupted data -- ok num-counter falsified KisculeError ok Edge bent into void Edge … points to unknown node 424242 ok NUL removed from end KisculeError ok Indent shifted KisculeError ok csize bent in header KisculeError ok byte flipped divergent

If any of these six fail, --verify returns exit code 1.

What is not tested: whether the game loads a rewritten script. The game was not started. Bit-exactness here means: identical bytes to Retail — not "accepted by the engine".

8. What a Mod Author Can Do With It

Safe, because it's just numbers (--set, one line):

python tools/kiscule.py --set gp_kiscule_devstarts \
  "edit.kiscule.nodes.item[8].parameters.object.delay=500" --out payload.bin

--set changes exactly one value and rebuilds the container. Without change, the result is byte-identical to Retail — verified. With change, Text and Container differ precisely at the intended location (calculated: 1 divergent byte for a single-character change).

Useful knobs, all in parameters.object:

Node Type Field What it does
Delay delay Wait time in ms — tempo of script chains
RandomTime min, max Scatter of repetitions
DamageNotification maxNotificationCount, waitingTime, filterDamageType what an object reacts to
GetCustomEvent enabled, maxNotificationCount disable or unlock a trigger
ActionBoolControl Bool switch flip script branches
ActionGiveItems Equipment lists what an event outputs
ActionAISpawn Spawn parameters enemy waves
ActionAutosave — save points
variables[].object.defaultValue starting value of a graph variable

Likely feasible but untested: bending edges. Bending an edge means adjusting endNodeID/endConnectionPointID at both ends — the mirror check in --verify catches it if you forget one. Adding nodes additionally requires a free id (32 bits, unique within the file) and matching connections; the signature table says what those are. Whether the engine accepts this: unverified.

The path to the archive is not part of this tool. --set --out delivers the finished user data; getting it into .resources is the job of wolfsdk/patch.py / tncpatch.py, and patch precedence (which archive wins) remains open in the project — see docs/moddingflaeche-tnc.md, section 7.

9. What Remains Open

  • version = 5 vs 6. Scripts carrying version 5: 64; scripts carrying version 6: 2329. No difference is visible in the structure. What distinguishes them for the engine: unknown.
  • properties-Bits 1, 4, and 32. Bit 16 (List) is set; bit 8 is the default case — the remaining bits appear in 2583 of 155,538 connections and are unassigned.
  • The id of an edge. It is often, but not always, the same at both ends (149,620 : 28,896). What else it means: unknown. It is unnecessary for reading the graph.
  • 43 dead edges in 29 Retail files, plus one file with duplicate connection IDs. Whether the engine silently skips them or if something is broken in the game there: unobservable without starting the game.
  • 84 scripts are duplicated in the archive, all 84 with different content. (--dump reports this.) Which version wins depends on patch precedence and is immeasurable — the same open question as for Decls.
  • 150 Entity references without a target in maps (1.10%).
  • The 113 unused node classes. They exist in the EXE. Whether a script can load them: untested.
  • g_kisculeRuntimeTypeChecks ("If 1, Kiscule will log all its runtime check verification", WINDOWS/DEBUG only) would be the direct way to let the engine talk about its own scripts via them. Not used — the game was not started.
