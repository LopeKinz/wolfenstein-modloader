In plain wordsIn einfachen Worten

Console variables (cvars) are the named settings of the game engine, such as field of view or HUD on/off. This page is the start of the full catalogue for Wolfenstein: The New Order, read from the game's own list in a memory snapshot of the running game. In this game most settings count as cheats: the game quietly resets them at start-up if you set them the normal way. The page explains which route works for which setting, which parts are proven in the game and which are only read from the code, and splits the cvars over three pages.

  • 3,194 cvars, all listed, with the developers' own description, the default value and, where the game defines one, the allowed range.
  • 2,865 count as cheats, because the engine makes every setting a cheat unless it is explicitly marked otherwise. A status column marks cheat, normal, saved, start-up-only and read-only settings.
  • A cheat cvar given as a launch option (+name value) is reset at start-up. 'toggle name value value' sets it anyway; the loader now does this, but it is not yet tested in the game.
  • Not cheats, so they work directly: g_permaGodMode, g_fov and g_damageScale. g_infiniteAmmo and pm_runspeed are cheats.
  • The console opens with Ctrl+^ according to the code (not yet tried); god, noclip, notarget, give and spawn do not exist in this game.

Technical detailsTechnische Details

Der technische Teil ist auf Englisch – so, wie er im Wiki steht. Unterstrichene Begriffe haben eine Erklärung auf Deutsch.

Generated by tools/build_cvar_wiki.py from the engine's own cvar registry. Edits made here are overwritten by the next run.

A cvar (console variable) is a named engine setting: field of view, HUD on or off, a damage factor, a debug overlay. Each one has a name, a type, a default value and usually a one-line help text written by the developers. This catalogue lists all 3194 cvars of Wolfenstein: The New Order with the engine's own description and default value, whether the game treats each one as a cheat, and the allowed range where the engine declares one.

Where the data comes from

  • Source: the engine's own cvar list. Every idCVar links itself into it when it is constructed, and the startup cheat reset walks the same list. It was read from a read-only memory capture of the running WolfNewOrder_x64.exe; nothing was launched for it. Raw data in the repository: docs/cvars_tno.json, written by tools/extract_cvars_tno.py.
  • Count: 3194 registered cvars, all listed, including the 8 read-only and 38 init-only ones.
  • Default is the reset value declared in the program, not a value seen in one session.
  • Range: 130 cvars declare a minimum and maximum, 4 a list of allowed values; the engine clamps a value to the declared range (read from the code). Empty means none is declared.
  • Description is the developers' help text, verbatim. 349 cvars have none (—).
  • Type: bool (1189), float (1054), int (788), string (163).

Status: cheat, normal, saved, init-only, read-only

Cheat is the default. The engine marks every cvar as a cheat unless it is registered as non-cheat, init-only, read-only or saved (read from the constructor). The Status column shows what that means for each cvar:

Status Count Meaning
cheat 2865 Wiped by the cheat reset at startup, refused when typed as name value. Set it with toggle (below).
normal 114 Not a cheat: +name value on the launch line works.
saved 169 Not a cheat, and the game writes the value to its own wolfConfig.cfg, so a value set once stays until it is set back.
init-only 38 Can only be set on the command line at startup.
read-only 8 Cannot be set at all.

How to set a cvar

Route Non-cheat cvar Cheat cvar Evidence
Launch argument +name value set, init-only ones included set, then wiped by the startup cheat reset; the log says Resetting cheat cvar: <name> measured in game (Modding-Limits §1)
Launch argument +toggle name value value set set: startup commands run after the reset, and toggle sets the value without the cheat check +toggle devgui (without values) measured surviving the reset (Modding-Limits §2); with values not yet tested in game, only read from the code
Console, name value set refused: <name> CANNOT be set in retail! read from the code; the same message is measured for .cfg lines
Console, toggle name value value set set read from the code, not yet tested in game
A line name value in a .cfg file set refused: WARNING: <name> CANNOT be set in retail! measured in game for 26 names, all of them cheat cvars; the 9 names measured as accepted are all non-cheat

toggle name value value always ends at that value: toggle cycles through the values given after it, and with the same value twice there is only one to land on. toggle name 0 1 flips between 0 and 1.

The console opens with Ctrl+^ (the key left of 1, with Ctrl held); com_allowConsole does not open it. This is read from the code and not yet tried in game.

The mod loader sends the Cheats & QoL tweaks and the "cvars" of a mod.json on the launch line: a non-cheat cvar as +name value, a cheat cvar as +name value followed by +toggle name value value, and it drops read-only cvars and names that are not cvars. The +toggle part has not been tested in game yet.

Commands that do not exist in The New Order, neither as commands nor as cvars: god, noclip, notarget, give and spawn. The closest substitutes are toggle g_permaGodMode 0 1 (a saved, non-cheat cvar) and the cheat cvar g_freeCam (a free-moving debug camera).
