In plain wordsIn einfachen Worten

This page compares what the project's documents and tool code claim, at first mostly about Wolfenstein: The New Order modding, and lists every place where they disagreed. Each of the 27 points says what was wrong, what was changed, or why it is still open; points W21 to W27 were added in October 2026 when later work corrected earlier pages. The rule was strict: where proof was missing, the text now says unverified instead of works. This matters because the whole project depends on keeping measured facts apart from guesses.

  • 17 of the first 20 points are fixed; 3 still need a game start or a Steam file check to close.
  • The game log shows that command-line cheat settings such as intro-skip are accepted and then wiped by a cheat reset.
  • A 48-minute game run with all 14 patched archives and 373 changed assets logged zero errors.
  • Several wrong numbers were remeasured, for example the virtual texture data is 39 files and 35.6 GB.
  • Added on 1 October 2026: SpawnAI is not a real command in the retail build (a static correction, never typed in game), and the cfile type is now usable, but only for small config files.
  • Added on 4 October 2026 (W23–W27): the loader read the older base copy of duplicated assets, the dev menu failure was placed wrongly, key binds in The New Colossus run restricted, a new map name needs far less than claimed, and TNC sounds and normal maps now have a write path.

Raised on 2026-09-21 by reading all files in docs/, comparing the header comments of all modules in wolfsdk/ against the code and against files on disk. Resolved on 2026-09-21.

This document is now a resolution log, no longer an issue list. For each of the 20 points, it states what was changed—or why it remains open.

Why this matters: this project sells itself on the distinction between measured and assumed. A document that treats an assumption as a measurement damages exactly that property—even if the assumption turns out to be correct. Therefore, when resolving issues, "missing" has never been softened to "works"; where evidence was lacking, it now states "unverified."

W6 — How big is a slot?

Fixed in text. Both Modding-Limits.md §4 and UI-Assets.md §3 now state that the budget is exactly csize. The up to 15 bytes of alignment padding between two payloads is not touched by the Patcher, because a shrinking csize shifts the addressing of all subsequent entries (No address, error: 487). Shorter streams are refilled to csize. Anyone calculating headroom calculates csize − own Deflate, as TNO-Modding-Surface.md §4.1 has always done.

Reported in code: wolfsdk/patch.py:12-13 — "A slot holds the entry's compressed bytes plus up to 15 bytes of alignment padding, which is usually enough headroom for an edited decl." This contradicts resources.write_in_place() and plan_in_place() in the same repository. Description only, no malfunction.

W17 — 80 or 84 text types?

Resolved, both sides using the counting rule. Recounted from the table in Engine-Modding-Surface.md: 105 types = 80 TEXT + 5 mixed + 20 binary. The five mixed types are sound, particle, renderProg, cuttableResource, and file.

TNO-Modding-Surface.md cites 84/21 because tools/survey_modding_surface.py does not know a "mixed" class: is_text() decides based on type at one sample (over 95% printable characters in the first 4096 bytes). Four of the five mixed types end up on the text side, one on the binary — 80 + 4 = 84, 20 + 1 = 21.

Both documents now carry the rule within themselves. "Directly editable without side effects" are the 80.

W18 — 60.233 Decls or 25.559?

Resolved, counting basis written for both numbers. 60.233 are index entries in text types, with multiple copies counted across several chunks. 25.887 are unique (type, name) pairs, of which 25.559 are valid UTF-8; the 328 outliers consist of 327 embedded binary files under file: and one renderProg. No measurement error, two counting bases.

Added to Home.md, File-Formats.md §4 (as a box), and TNO-Modding-Surface.md (header).

W20 — What Really Lies in the Backup?

Resolved — and harmless. The observation was correct (all 14 .index and all 14 .resources, totaling 2.98 GB), but the conclusion was not. The journal explains it fully:

journal.json:  rebuilt = 14 files,  slots = 0,  assets = 373

All 14 archives had to be rewritten, so _backup_resources() created a full copy for all 14. This is exactly the described procedure and not a puzzle. apply() also resets first before copying — thus the copies come from the reset state.

Home.md now describes the folder correctly, citing the range from a few tens of MB to around 3 GB and the journal key rebuilt. File-Formats.md §3 describes the reset in three stages and explicitly states that a .resources is never truncated.

Verification check, purely reading: All 14 backup .resources have exactly the original length from manifest.json (14 of 14, 0 deviations).

One remaining open question: verify_backup() checks the sha256 of the indexes, not the .resources — the manifest stores only size and timestamp for these. That the full copies are bit-exact is likely but unproven. A fresh Steam file check would be decisive. Until that is done, a small question mark remains after Audio.md and TNO-Modding-Surface.md, which derive their numbers from this folder; it is small because the lengths match and revert was sha256-identical over two cycles.

The corrected line now stands consistently in Research-Report-R4-Console-Commands, Research-Report-R5-Kiscule-Command, TNC Console Unlock, and TNC Modding Surface.

W22 — cfile was "proven not possible", then solved — scope of the fix

TNC-Modding-Surface.md §0/§6 (surveyed before the key derivation existed) rated cfile as "proven not possible (yet)", reading the type as a closed door onto strings/*.lang and the .cfg configs together. The key is now derived and round-trip proven (Research-Report-Cfilekey2), and the loader uses it in a running game — but only to replace small, unused configs for the console-unlock recipe, not to edit the localization files. TNC-Modding-Surface.md §6 has been updated in place with a correction box rather than rewriting the original (still largely accurate) analysis; Home.md's capability table now lists cfile and the console/Cvar restriction as separate, both works, measured rows. Not a contradiction between documents — a capability that moved from "proven not possible" to "possible, with a narrower scope than the original question asked about" between surveys, worth stating explicitly so no one re-reads the old verdict as still current.

New Since 2026-10-01 (added 2026-10-04)

Five points, resolved by the dev menu, custom map and WolfSDK 0.2.0 release work. Logged the same way as above: what was wrong, and what fixed it.

W23 — The loader read the older base copy of duplicated assets

Fixed in code and text. tncpatch.Installation.read took the first hit when an asset exists more than once. The reasoning was that the choice is harmless, because the loader writes its result into every copy anyway. That is the flaw: writing every copy makes the copy that was read the base of all of them. chunk_* sorts before patch_*, so the first hit was the older base copy; of 1,680 base/patch collisions the patch copy is the newer one 1,635 times. A mod could therefore undo official patch changes in the assets it touched. Since WolfSDK 0.2.0 the loader reads the newest patch_N copy, the one the Studio already showed. Now in Patch Precedence sections 8–9 and Kiscule Scripting §8–9.

W24 — Where the TNC developer menu fails

Fixed in text. Earlier pages put the failure in the wrong place:

  • TNC Custom Map Status called map and devmap "unknown" and "removed". Both are registered; the console only does not expose them.
  • Research-Report-R3-Swfui called the dev menu "a dead end for TNC", because debugmenu.txt is absent. That file belongs to The New Order's route; The New Colossus has its own menu of devMenuOption decls.
  • The first dev menu analysis held that only a native handler could repair the menu.

What is true: map entries queue loadDevMenuOption, which retail never registers. Entries with command lines run them at level 0, and devmap from the menu loads the map, confirmed in game on 2026-10-02. Still not reproduced: Progression and give. Corrected inline in TNC Custom Map Status; new page TNC Dev Menu. The research reports stay as written.

W25 — Key binds in The New Colossus run restricted

Fixed in code and text. TNC Console Unlock §1 listed six places that raise the restriction level, and the loader gave The New Colossus default F1–F4 binds (toggle ..., noclip). A later full scan (report r8) found one more bracket: the key-bind dispatcher buffers a bound command into the restricted buffer at level 1. Those binds could not work. The loader no longer binds keys for The New Colossus; a key bound to resourceExec <cfile> -s does work, which Sandbox Tools and Photo Mode use. Now in TNC Console Unlock §1 (note) and §7.

W26 — A new map name needs far less than claimed

Fixed in text. TNC Custom Map Status said a truly new map ID needs IDCL identity, save and menu registration, and possibly PVS and navmesh changes together. Confirmed in game on 2026-10-02: game/wolfsdk/modtest loads. It needs only the name in dlc/dlc_0/base/packagemapspec.json, a textures.cache link under the new name, and the map-level entries renamed in the container. Corrected inline and in new sections of TNC Custom Map Status.

W27 — TNC sounds and normal maps: from "no write path" to built

Fixed in text. A capability change, as W22 was. Audio §0, §6 and §7 said TNC audio has no write path and no bank parser. Both exist now; the sound replacement is built (held back in 0.2.0 because Revert did not yet restore replaced sound packs; enabled since 0.3.0). TNC Texture Database §4b and §6 said tile chains block replacement and a longer block forces a full rewrite. Normal maps are now written as plain BC5 under codec 1 without decoding tile chains, and longer blocks are appended. Neither is confirmed in game. Correction notes in place, new sections at the end of both pages.
