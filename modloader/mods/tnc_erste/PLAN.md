# Dry-run plan tnc_erste

Generated by `tools/build_tnc_mod.py`. Every number comes from
`Archive.plan_in_place()` or from the archive's entry table.
The installation was only read -- neither
`write_in_place()` nor `rebuild()` nor `apply()` was called.

## Touched archives

* `gameresources.resources` -- 702,059,123 bytes (669.5 MiB), 50,839 entries

Nothing else. The other 23 `.resources` stay untouched, as do all
`.texdb`. A backup for the mod therefore costs exactly this one file.

With mode 0, "New payload" is the usable size itself -- these entries
are stored uncompressed, and `pack_payload` leaves them that way: below about
150 bytes, Kraken costs more than it saves. The mode therefore stays 0 in
all seven cases.

## What the budget really is

The column "Budget csize+gap" is here because
`docs/moddingflaeche-tnc.md` section 4.1 lists the zero-filled gap as
growth reserve. **`plan_in_place()` does not use it.** For
mode 0 it requires `len(payload) == csize`, for mode 2
`len(payload) <= csize`; in both cases the gap is left out.
It could not do otherwise: `write_in_place` only writes `usize`
and the mode byte back into the table, `offset` and `csize` stay
as they are. Anyone who wants to grow into the gap needs a write path
that updates `csize` as well -- that does not exist today. At
4 to 6 bytes, the gaps here are too small to save anything anyway.

For this mod it makes no difference: every replacement has the same length, the
rest is 0 everywhere, the gap is not needed.

Checked: all 7 gaps (34 bytes together) really are
zero bytes -- read, not assumed.

## If an entry did not fit

It fits, but the fallback plan still belongs on paper, because it
is needed right away for any larger change to the same decls:

1. **Keep the same length.** With mode 0 this is the only way that
   works without rebuilding the archive. Every value with the same
   number of digits is reachable: for `0.5` that is `0.0` to `9.9`, for `0.75` `0.00` to
   `9.99`. That covers every sensible damage scaling.
2. **A different entry.** The same effect also lives in
   `entityDef:player` (`healthOverrides` -> `healthComponent`), but that one is
   Kraken-compressed (csize 2581, usize 13165, gap 43).
3. **`rebuild()`.** Costs rebuilding `gameresources.resources`:
   702,059,123 bytes, 50,839 entries, at a measured 26.9 MiB/s Oodle
   throughput about 25 seconds of computing time plus 670 MiB of disk space for
   the backup. For 14 changed digits that is obviously the
   wrong way -- which is why the lever was chosen so that it is not
   needed.

## Counter-checks

Each of these stops the build if it does not hold:

1. **Duplicate test.** Each of the seven tables appears exactly once across all 24
   archives. If there were a second copy in a
   `patch_*.resources`, the unmeasured load order would decide whether
   the mod does anything at all.
2. **Version lock.** The retail value of every field is checked against the
   expected one before anything is replaced.
3. **Empty round trip.** `Decl(text).render()` without a change must
   return bit-identical text.
4. **Span check.** The edited text is compared byte by byte with the
   original; every differing byte must lie within one of the two
   value spans, and the total length must stay the same. A
   mod that shifts formatting on the side fails here.
   Plus the way back: the edited decl is parsed again, must
   have the same set of paths as before and yield the new values.
5. **Not fitting must not fit.** `0.000` and `0` are deliberately
   sent through `plan_in_place()` and **must** return `None`:
   too long (62 instead of 58 bytes) and too short (54 instead of 58). If one
   of them got through, the write path would run into the neighboring payload or
   leave the rest of the slot standing.

That these checks do not just pass but really bite is
shown by `python tools/build_tnc_mod.py --gegenprobe`: six deliberately
wrong versions, each must stop the build. Two of them bypass the
pre-checks of this script and hit `plan_in_place()` directly.
If the assertions are disabled, the run reports
`GEGENPROBE GESCHEITERT` and ends with code 1 -- reproduced and
confirmed.

## What is not checked

* Whether the engine reads `min 0.0 max 0.0` as "no damage" or
  treats a degenerate table value differently. The game was not
  started.
* Whether `data_hash` in the entry table is checked. `idcl.py` leaves
  it as it is; no known hash function reproduces it.
* Whether the gap behind a payload has a second meaning.
  This mod does not need it, so the question does not arise here.
